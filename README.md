# Performance Optimizer 4.1.0

SillyTavern의 긴 대화 렌더링과 확장 자체의 불필요한 작업을 줄이는 개선판입니다.
기존 설정 키와 개별 모듈 스위치를 유지합니다.

## 주요 변경

- 메시지를 강제로 숨기고 고정 높이를 지정하던 가상화를 `content-visibility: auto` 기반으로 교체했습니다. 전체 메시지 높이 순회와 반복적인 맨 아래 강제 스크롤을 제거했습니다.
- 화면 근처 메시지, 최근 메시지, 편집 중인 메시지는 렌더링을 유지합니다. 화면 밖 본문도 DOM에 남아 브라우저 검색과 선택에 접근할 수 있습니다.
- 긴 메시지 접기는 화면에 보이는 완료 메시지만 측정합니다. 생성 중인 마지막 메시지는 접지 않으며, 프레임 최적화를 켜면 높이 읽기와 화면 변경을 분리합니다.
- 새 이미지 처리는 채팅 영역으로 한정하고 프레임당 중복 노드를 합칩니다. 제거된 이미지 참조를 해제하고, 모듈이 추가한 속성만 복구합니다.
- 아바타 Blob 캐시를 제거했습니다. 브라우저 이미지 캐시와 지연 로딩/비동기 디코딩을 사용하므로 추가 fetch와 오래된 이미지로 덮어쓰기가 발생하지 않습니다.
- 네트워크 모듈은 같은 서버의 정적 리소스에 대한 옵션 없는 GET 동시 요청만 합칩니다. Request 객체, 옵션이 있는 요청, 외부 서버, 일반 API 호출은 그대로 전달합니다. 메모리에 완료된 응답을 보관하지 않으며 추적 중인 요청은 최대 32개입니다.
- jQuery 크기/위치 측정값 캐싱, scrollTo 교체, 프롬프트 sortable 초기화 생략을 제거했습니다. 프롬프트 최적화는 CSS로 적용하고 정렬 중에는 전체 항목을 렌더링합니다.
- 모바일의 반복적인 공백 텍스트 순회/삭제, 전체 채팅 GPU 레이어 강제 생성, 빈 콜백만 실행하던 textarea 옵저버, 전역 resize 차단과 textarea focus 교체를 제거했습니다.
- 배경 변환 결과가 새 배경을 덮어쓰지 않도록 검사하고 폐기된 Blob을 해제합니다. 변환 캐시는 최대 4개이며 확대 변환과 통계용 HEAD 요청을 생략합니다. GIF/WebP/APNG 경로는 애니메이션 보존을 위해 변환하지 않습니다.
- 설정 재적용 시 이벤트/옵저버 중복 등록을 막고, 잘못된 모듈 설정 형식을 기본값으로 복구합니다.

## 적용

SillyTavern 페이지를 새로고침하면 변경된 모듈이 로드됩니다. 이전 코드의 전역 패치와 Blob이 남을 수 있으므로 새로고침 없이 파일만 바꾸는 것으로는 적용이 끝나지 않습니다.

설정 패널에서 각 기능을 끄거나 전체 최적화를 끌 수 있습니다. 긴 메시지를 자동으로 접고 싶지 않으면 접기 높이를 0으로 설정하세요.
기존의 SillyTavern 빠른 UI/블러/모션 설정은 원래 모듈의 동작대로 저장되며, 전체 스위치를 끄는 것만으로 되돌리지 않습니다. 해당 값은 기존 설정 복원 기능 또는 SillyTavern 설정에서 조정할 수 있습니다.

기존 `_patch_v31.cjs`는 이전 버전 코드 생성용 파일입니다. 개선판을 적용한 뒤 실행하지 마세요. 확장 로딩에 필요한 파일은 `manifest.json`, `index.js`, `style.css`, `modules/`입니다.

## 검증과 한계

Chrome의 별도 시험 페이지에서 브라우저 동작과 회귀 검사 11개를 통과했습니다. SillyTavern의 로컬 jQuery와 모의 확장 컨텍스트를 사용해 전체 초기화 및 반복 토글도 검사했습니다.

- 1,000개 메시지: 기존 가상화의 `offsetHeight` 읽기 992회 → 개선판 0회. 개선판에서 강제 하단 이동이 발생하지 않았습니다.
- 600개 긴 메시지: 화면 상단 시험에서 접기용 높이 읽기 2회. 펼치기와 마지막 메시지 보호를 확인했습니다.
- 검색, 편집, 폭 변경, 이미지 속성 복구, 요청별 응답 본문 분리, Request/취소 옵션 전달, 실패 후 재시도, 다른 확장의 fetch 래퍼 보존, 배경 비동기 작업 폐기 및 모듈 해제를 검사했습니다.

위 숫자는 시험 페이지의 코드 호출 횟수이며 FPS나 실제 사용 속도 향상률을 뜻하지 않습니다. 사용자의 실제 대화·모든 테마/확장 조합 및 실물 모바일 키보드는 테스트하지 않았습니다. AI 서버의 응답 생성 속도나 회선 지연은 이 확장의 최적화 범위 밖입니다.

브라우저 렌더링 생략을 사용하므로 처음 보는 긴 메시지의 추정 높이가 실제 높이로 바뀔 때 스크롤바 길이가 조정될 수 있습니다. 가상화 옵션을 끄면 일반 렌더링으로 돌아갑니다. 이 방식은 DOM 자체를 제거하지 않으므로 메시지의 DOM 메모리까지 줄이는 기능은 아닙니다.

브라우저 기능 참고: [MDN content-visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/content-visibility), [MDN contain-intrinsic-size](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/contain-intrinsic-size).
